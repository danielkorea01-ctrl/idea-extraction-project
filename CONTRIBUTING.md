# Contributing

We welcome corrections, counterexamples, reproductions, and evidence that weakens the hypotheses. All public project contributions should be in English.

## Submit an issue or pull request

Use this structure:

1. **Claim ID and proposal:** Identify the claim you want to add, test, correct, or retract.
2. **Evidence label:** Fact, documented claim, inference, hypothesis, or unverified assumption.
3. **Source:** Primary URL, document date/version, relevant section, and access date.
4. **Scope:** Product, dataset, timeframe, jurisdiction, and conditions where relevant.
5. **Support and limits:** Explain exactly what the source establishes and what it does not.
6. **Alternatives:** Provide competing explanations and contradictory evidence.
7. **Reproduction:** For experiments, include authorized data, code, configuration, and results.
8. **Requested revision:** State which wording or research step should change.

Do not post credentials, private third-party conversations, identifying information, trade secrets, or material you lack permission to disclose. Use synthetic examples or consented, appropriately minimized data. Do not attempt unauthorized access or solicit confidential company records.

A submission is not automatically a verified fact. Review must check source authenticity, scope, evidence-to-claim fit, alternatives, and privacy. Mark unresolved disagreements visibly. Keep corrections traceable in Git history.

No license has been selected. Do not assume that public visibility grants unrestricted reuse rights.
